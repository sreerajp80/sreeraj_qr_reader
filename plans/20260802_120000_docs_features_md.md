# Add docs/features.md — full feature list of the app

**Status:** completed

## What is the issue

There is no single document that lists all the features of this app in one
place. The user wants a `docs/features.md` file. This file will be shared
with another LLM (used in other app projects) so it can check what this app
already does before adding a new feature there. It must be complete and
correct in one pass.

## Files to be changed

- `docs/features.md` (new file only — no other file is touched)

## Plan for the fix

Create `docs/features.md` with:

1. A short paragraph describing what the app is: an offline-first, Android-only
   Flutter app that scans QR codes and barcodes, and checks scanned links for
   safety (phishing, fake sites, tampered codes), plus extra tools like hidden
   QR codes, smart actions for Wi-Fi/contacts/payments, scan history, and an
   optical air-gapped data transfer mode.

2. A full feature list, grouped under clear headings:
   - Core scanning (camera, formats, zoom, torch, gallery/PDF/share-sheet scan)
   - URL safety & anti-phishing (6-layer check engine, private vs active probing)
   - Zero-trust link preview (DOM sandbox)
   - Quishing Guard (physical sticker/tamper detector)
   - StegoQR (hidden, biometric/passphrase-locked QR content)
   - Smart payload actions (Wi-Fi, contact, geo, calendar, payment/UPI, 2FA/TOTP)
   - Scan history & database (search, filter, export, encrypted backup)
   - AirQR (optical air-gapped transfer)
   - AR CodeVision (live multi-code camera HUD)
   - Theming & UI (Material 3, dark/OLED, dynamic color, settings)
   - Security & privacy (key storage, encryption, permissions, no backup of secrets)

3. A short "Key technical facts" section: Flutter/Android-only, min/target SDK,
   state management (Provider), offline-first behaviour, supported barcode
   formats, main dependencies, no cloud sync/accounts.

This content comes from the source in `lib/`, `pubspec.yaml`, and the
`change_log/` folder (the change logs are the up-to-date record of features;
`docs/architecture.md` and `docs/security.md` are known to be out of date and
will not be treated as the source of truth for this list).

This is a documentation-only change. No app code, tests, or config are
touched.

## After approval

Once approved, `docs/features.md` will be created, and a change log entry
will be written in `change_log/` describing the new file.
